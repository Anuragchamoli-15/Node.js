
1. V8 इंजन की JIT कंपाइलेशन प्रक्रिया (How JIT Works)

पुराने समय में ब्राउज़र जावास्क्रिप्ट को इंटरप्रेट (Interpret) करते थे, यानी कोड को लाइन-दर-लाइन पढ़कर रन करते थे, जो कि काफी धीमा था। V8 ने JIT (Just-In-Time) कंपाइलेशन का उपयोग करके इसे पूरी तरह बदल दिया। यह कोड को रन करने से ठीक पहले मशीन कोड में बदल देता है।
V8 की आंतरिक संरचना मुख्य रूप से दो भागों पर काम करती है:


[ JavaScript Code ] 
         │
         ▼
 ┌──────────────┐
 │   Ignition   │  (Interpreter: कोड को जल्दी शुरू करता है और Bytecode बनाता है)
 └──────┬───────┘
        │
        ├─────────► [ Profiler: देखता है कौन सा कोड बार-बार चल रहा है (Hot Code) ]
        │                                  │
        ▼                                  ▼
 ┌──────────────┐                  ┌──────────────┐
 │   Bytecode   │                  │   TurboFan   │ (Optimizing Compiler: कोड को 
 └──────────────┘                  └──────┬───────┘  सुपर-फास्ट मशीन कोड में बदलता है)
                                          │
                                          ▼
                                   [ Optimized Code ]

                                   
• Ignition (इंटरप्रेटर): जैसे ही आप कोई जावास्क्रिप्ट कोड चलाते हैं, Ignition उसे बहुत तेज़ी से बाइटकोड (Bytecode) में बदल देता है। इससे आपका प्रोग्राम बिना किसी देरी के तुरंत शुरू हो जाता है।
• Profiler (निरीक्षक): जब कोड चल रहा होता है, तो बैकग्राउंड में एक प्रोफाइलर नज़र रखता है। यह देखता है कि कोड का कौन सा हिस्सा (जैसे कोई फंक्शन या लूप) बार-बार चल रहा है। इस बार-बार चलने वाले कोड को "Hot Code" कहा जाता है।
• TurboFan (ऑप्टिमाइज़र): प्रोफाइलर इस "Hot Code" को TurboFan कंपाइलर के पास भेज देता है। TurboFan इसे अत्यधिक ऑप्टिमाइज़ करके सीधे मशीन कोड (Machine Code) में बदल देता है। इसके बाद, वह कोड सीधे आपके कंप्यूटर के प्रोसेसर पर बिजली की रफ्तार से चलता है।
• Deoptimization (डीऑप्टिमाइजेशन): जावास्क्रिप्ट एक डायनेमिक भाषा है (जहाँ वेरिएबल्स का डेटा टाइप बदल सकता है)। अगर TurboFan द्वारा ऑप्टिमाइज़ किए गए किसी फंक्शन में अचानक से अलग टाइप का डेटा आ जाता है, तो V8 समझदारी से उस कोड को वापस 'Deoptimize' करके नॉर्मल बाइटकोड पर ले आता है ताकि एरर न आए।

2. Node.js के साथ V8 कैसे काम करता है? (V8 inside Node.js)

मूल रूप से, जावास्क्रिप्ट को केवल ब्राउज़र (जैसे क्रोम, फ़ायरफ़ॉक्स) के अंदर चलने के लिए डिज़ाइन किया गया था ताकि वेबसाइटों को इंटरैक्टिव बनाया जा सके। इसका मतलब था कि जावास्क्रिप्ट आपके कंप्यूटर की फाइलों को पढ़ नहीं सकती थी और न ही कोई नेटवर्क सर्वर बना सकती थी।
2009 में, रयान डाहल (Ryan Dahl) ने क्रोम के ओपन-सोर्स V8 इंजन को ब्राउज़र से बाहर निकाला और उसे C++ के कुछ अन्य टूल्स (जैसे libuv) के साथ जोड़ दिया। इसी कॉम्बिनेशन को हम Node.js कहते हैं।
Node.js में दोनों मिलकर इस तरह काम करते हैं:
• दिमाग (V8 Engine): Node.js में जावास्क्रिप्ट कोड को समझने और प्रोसेस करने का पूरा काम V8 इंजन ही करता है। यह कोड को पढ़ता है और उसे मशीन कोड में बदलता है।
• हाथ-पैर (C++ APIs & libuv): V8 अकेले कंप्यूटर के हार्डवेयर (जैसे फाइल सिस्टम, नेटवर्क, डेटाबेस) से बात नहीं कर सकता। इसलिए Node.js इसे C++ बाइंडिंग्स और libuv लाइब्रेरी की ताकत देता है।
• उदाहरण: जब आप Node.js में fs.readFile() लिखते हैं, तो V8 उस कोड को कंपाइल करता है, और Node.js उसे आपके कंप्यूटर की हार्ड डिस्क से फाइल रीड करने के लिए C++ बैकएंड पर भेज देता है।
संक्षेप में कहें तो: V8 इंजन वह रॉकेट इंजन है जो जावास्क्रिप्ट को सुपर-फास्ट स्पीड देता है, और Node.js वह ढांचा है जो इस इंजन को हवाई जहाज या रॉकेट की तरह सर्वर-साइड पर उड़ने की आज़ादी देता है।
